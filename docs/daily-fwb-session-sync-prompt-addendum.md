# Daily FWB Session Sync — monthly Coach total

Append the block below to the existing **Daily FWB Session Sync** task after the Coach web app and its monthly-total migration are deployed. Do not replace the existing task instructions or change the task's activation or schedule.

---

After the normal daily reconciliation, also refresh **FWB sessions** in the Coach web app's **Sessions** tab. This is a separate business tally, not a client package balance or an Alex Fitness gym tally. Do not apply the package-billing rules to this tally. Update the aggregate only; this step must not write to Alex Fitness, client packages, the calendar, or the spreadsheets.

- Use the existing FWB Calendar and verified attendance sources. Each run recalculate the current Pacific calendar month through the reconciliation cutoff and the immediately preceding Pacific calendar month in full, so missed days and month-end corrections are picked up. Read every page. For each month, use its local midnight as the lower bound and the earlier of the next local month boundary or the current run time as the cutoff. Do not count future slots or sessions still in progress.
- Count a verified completed FWB training session as **completed**, or a verified cancelled FWB training appointment as **cancelled**, chargeable or not. Use the appointment's scheduled start date in `America/Los_Angeles`, not the date the cancellation was recorded. Include explicitly identified cancellation entries even when the client balance was not changed. Do not count non-training or personal events, no-shows that were not recorded as cancellations, ambiguous records, or a reschedule as both a cancellation and a replacement unless the original slot is explicitly recorded as a distinct cancellation. Check identifiable cancelled/deleted events where the connector exposes them. Do not assume an event was completed just because it ended or guess what an unidentified deletion was.
- Deduplicate by the calendar occurrence ID (for recurring sessions include the occurrence's original start time) and the existing same-client/date/start-time duplicate check. Use calendar and sheet records to verify the same appointment, not as two sessions. Two different sessions for the same client on the same day can count separately. Publish only when the reconciliation has enough verified coverage for that month. If access, pagination, or identifiable session records are incomplete, leave the earlier total unchanged and report what could not be verified. Save a zero only when the sources verify zero.
- On the existing verified FWB Supabase project, use the existing authorized SQL connector to call `public.save_coach_fwb_monthly_session_total(p_month_start, p_through_at, p_completed_count, p_cancelled_count)` once per verified month. Pass the first day as a date, the cutoff as a timestamp with offset, and the two nonnegative integer counts. Send only aggregates, not calendar IDs, names, or client details, to this function. The write replaces the monthly snapshot; do not increment a previous total. Re-read `public.coach_fwb_monthly_session_totals` for that month to verify both counts and coverage. If the function or authorization is unavailable, do not work around it or change any permissions; report that the monthly Coach total could not be published.
- Include a short line in the existing task summary for each updated month: `FWB sessions: X total (Y completed + Z cancelled)`. Leave Alex Fitness unchanged.
